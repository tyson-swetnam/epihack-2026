Knowledge graph

The structured content above is mirrored in SQL seeds for a property graph encoded in DuckLake (with Postgres as the catalog) and queried via DuckDB. DuckLake is the web + analytics store; the mobile app writes to MongoDB, synced back into DuckLake so the agents, MCP servers, and cluster detection see one dataset (plan 09):

  • schema/knowledge_graph.sql — core nodes, edges, properties from Figures 1–4.
  • schema/system_designs.sql — worksheet template, focus areas, completed designs.
  • schema/world_cafe.sql — World Café Q4 engagement examples and tactics.
  • schema/wildlife_vectors.sql — wildlife / vector-borne focus group, four questions, and 30+ anchor resources across state, county, tribal, federal, academic, and citizen-science jurisdictions.
  • schema/heat.sql — Heat focus group, four questions, vulnerable populations, and 30+ heat-specific resources (ADHS BRACE, MAG HRN, Phoenix OHRM, NWS HeatRisk, UA Heat Resilience Initiative, CLIMAS, 211 Arizona).
  • schema/deep/ — deep-research seeds: all 15 AZ counties, all 22 tribes, pathogens, historical outbreaks, datasets & APIs, interop standards, MCP servers.

See the schema landing page for the full file index, bootstrap commands, and example queries, or the README for the project-wide walk-through.
