AZ One Health Sentinel

A mobile-first participatory-surveillance stack for Arizona — built at EpiHack Arizona 2026. One Next.js reporting app, an eight-agent FastAPI backend, eleven MCP servers, and a DuckLake-on-Postgres knowledge graph — all preserved end-to-end so a future revival can start from a known-good baseline.

The journey, in six steps

A first-read map. Each step links to its full chapter in the docs site.

1

Frame

The ten-prompt design worksheet, two focus groups, and the figures that anchored every decision.

 2

Map

Thirty-plus anchor APIs picked from across state, tribal, federal, academic, and citizen-science sources.

 3

Build MCPs

Eleven FastMCP servers, scaffolded from one template, all testable offline.

 4

Store

DuckLake-on-Postgres for web/analytics, MongoDB for mobile writes, one property-graph schema.

 5

Orchestrate

Eight Pydantic agents behind FastAPI, gated by a privacy contract encoded in code.

 6

Ship the app

Next.js 16, anonymous-first, EXIF-stripped, with profile enrichment and a personal dashboard.

How the pieces fit

Four loosely-coupled tiers behind one origin. A mobile report enters the top and lands in the store at the bottom; advisories ride back up the same path.

Client tier

📱 Next.js mobile/web app 🖥 Agency dashboard 🌎 Public "Today" view 🗺 MapLibre map 🧬 Pathogen graph 🦆 DuckDB-WASM query
↕ X-Client-Channel: mobile | web

Agent tier — FastAPI orchestrator

Intake Geo Validation Triage Enrichment Notification Cluster KnowledgeUpdate
↓ per-prefix dispatch (vectorsurv_*, kg_*, …)

MCP tier — 11 FastMCP servers

↓ writes

Storage tier

📚 MongoDB · mobile writes 🏞 DuckLake (Parquet) · web + analytics 🐘 Postgres · DuckLake catalog ⏱ 5-min Mongo → DuckLake sync
