DuckLake schema

SQL seeds for the EpiHack Arizona 2026 knowledge graph — a property graph encoded as kg.node / kg.edge / kg.property tables, stored in DuckLake (Postgres catalog + Parquet data), queried with DuckDB.

Why DuckLake + DuckDB + Postgres

LayerRole
Postgres DuckLake catalog: snapshot metadata, schema evolution, ACID transactions over the lakehouse.
DuckLake Open lakehouse format on top of Parquet, catalog in Postgres. Time travel, branches, and multi-writer concurrency without having to stand up Iceberg/Hudi infrastructure.
DuckDB Embedded query engine. Reads/writes DuckLake natively; can join Parquet, Postgres, and CSV in a single SQL statement; works on a laptop and at hack-day scale.

Bootstrap

# 1. Postgres for the DuckLake catalog
createdb epihack

# 2. DuckDB session
duckdb
-- Inside DuckDB:
INSTALL ducklake;  INSTALL postgres;
LOAD    ducklake;  LOAD    postgres;

ATTACH 'ducklake:postgres:dbname=epihack host=localhost user=epihack'
  AS epihack
  (DATA_PATH 's3://epihack/ducklake/');     -- or a local path for laptop dev

USE epihack;

-- Core graph (run first)

Example queries

After loading, the graph is queryable in plain SQL. A few starters:

-- All parameters in the Exposure class (Figure 2)
SELECT n.label
FROM   kg.edge e
JOIN   kg.node n ON n.node_id = e.subject_id
WHERE  e.predicate = 'belongsTo'
  AND  e.object_id = 'category.exposure';

-- Outbreak timeliness intervals (Figure 3)
SELECT * FROM kg.v_outbreak_timeliness;

-- Which MCP tools answer Wildlife Q1?
SELECT s.label AS mcp_server, t.label AS mcp_tool
FROM   kg.edge ei
JOIN   kg.node t ON t.node_id = ei.subject_id
JOIN   kg.edge eb ON eb.subject_id = t.node_id AND eb.predicate = 'exposedBy'
JOIN   kg.node s ON s.node_id = eb.object_id
WHERE  ei.predicate = 'informs'
  AND  ei.object_id = 'wv.q1';

-- Convenience: every MCP server with the API it wraps
SELECT * FROM kg.v_mcp_servers;

Conventions for new seeds

  • Idempotent: every INSERT uses ON CONFLICT DO NOTHING, so re-running a seed is safe.
  • Edge ID ranges: each file reserves a numeric block (e.g. 16000–16999 for mcp_servers.sql, 40000–40999 for audit.sql, 50000–50999 for cluster_followups.sql). New seeds should pick the next free block and document it in the header comment.
  • source_fig: every node and edge carries a source_fig tag so any row can be traced back to the figure, focus group, or sub-agent that introduced it.
  • Views in kg.v_*: convenience views are defined in the seed that owns their data and exposed under the kg.v_ prefix.
